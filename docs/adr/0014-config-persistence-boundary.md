# ADR-0014：配置文档通过外围适配器持久化并协调 Loader

> 状态：Proposed<br>
> 类型：ADR<br>
> 日期：2026-09-05

## 背景

[ADR-0009](./0009-loader-entry-tree.md) 将 Loader 定义为内存 Entry 树与生命周期协调层，文件持久化需要通过公开 API 接入。现有 [Entry 类型](../../packages/loader/src/types.ts) 同时包含未知类型配置、Symbol 隔离标签和运行时快照；组件还可以动态创建 Entry，因此整棵树不能直接作为可往返的 JSON 文档。

[Loader](../../packages/loader/src/loader.ts) 的配置与启动失败可能通过 `failed` 快照返回，删除也可能在实际移除条目后报告清理错误。现有 API 不提供跨文件和运行时的批量事务，持久化适配器必须明确目标保存与实际执行之间的差异。

## 提议决策

1. 新增外围配置适配器，暂用 `@nya/include` 名称；文档解析、规划、存储与执行在包内分层。Core 和 Loader 的现有公开边界保持不变，首版支持单个版本化 JSON 文档和单宿主写入。
2. 文档保存有限 JSON 数据和稳定声明身份，运行诊断留在运行时。隔离标签使用文档作用域的字符串映射，保持同一控制器内的 Symbol 身份稳定。
3. 适配器持有文档目标及明确的受管 ID，只对自身声明发起直接树操作。动态与宿主条目不自动回写；删除受管父级仍遵循 Loader 的所有权级联清理，预览呈现当前树中可确定的结构影响。Core 依赖传播可能改变其他条目的运行状态，生命周期副作用需由执行报告记录，纯预览不承诺穷尽。
4. 程序化变更先静态预检、规划及检查文件基线，再提交目标文件，最后通过 Loader 公开操作协调。分别报告保存结果、部分执行和逐 Entry 状态，不承诺运行副作用的原子回滚。
5. 文件替换使用同目录临时文件；冲突检测限定在单写者模型内，不声称对任意外部进程提供原子比较交换。外部无效配置保留当前已接受目标，不自动回写覆盖。
6. 文件监听作为同一协调入口的可选触发源，后于手动持久化交付。HMR 需要独立设计；导入解析不属于无副作用预检，Loader 的 `resolve()` 保持显式失败恢复语义。
7. 控制器的观察、排队任务和文件资源有明确所有者与关闭流程，借用的宿主 Root/Loader 不由它关闭。新能力不复制 Core 的私有 Schema 验证或生命周期实现。

## 后果

能够复用 Loader 的身份与生命周期协议，配置文件和管理入口也能共享同一套目标及执行报告。首版范围可控制为单文件加载、编辑保存和重启恢复。

磁盘目标可能有效但组件暂时无法运行；宿主需要展示保存成功与运行失败的区别，并允许显式修正或恢复。运行时应用过程中可观察到中间状态，组件副作用也不能靠改回 JSON 保证撤销。

JSON 数据边界会限制程序化运行时对象的直接持久化；多来源合并、任意对象编码、多进程写入和 HMR 必须在后续扩展时另行确定契约。

## 考虑过的替代方案

- 直接序列化 `loader.entries()`：混合运行状态、动态声明和不可序列化值，无法可靠定义归属与往返行为。
- 将文件读写并入 Core 或 Loader：扩大现有职责，与 ADR-0009 的外围适配边界冲突。
- 运行成功后才保存，并自动回滚所有失败：缺少事务性副作用和保证可执行的恢复操作；文件失败仍会留下内存变化，无法兑现原子性。
- 首轮同时实现 YAML、跨文件 include、监听与 HMR：引入来源归属、循环引用、模块图和缓存协议，推迟单文件闭环的验证。
