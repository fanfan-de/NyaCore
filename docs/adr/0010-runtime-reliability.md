# ADR-0010：生命周期重入与清理失败恢复

> 状态：Proposed<br>
> 类型：ADR<br>
> 日期：2026-09-05

## 背景

Loader 的队列可能等待 Component 清理，而清理又等待 Loader 创建或修改条目。只识别直接等待的 Fiber 会漏掉所有权后代和服务失效触发的其他分支消费者。删除期间新建后代、解析输入变化后复用旧定义以及 Registry 覆盖清理错误，也会让 Entry 与实际运行状态不一致。

Core 的主动清理必须同时解除所有者栈引用；清理重入和日志 sink 失败也必须遵循同一所有权协议。

## 决策

### 清理入口与所有权

所有清理入口在调用用户代码或发出清理日志前缓存 Promise。重复调用复用任务，整栈清理开始后禁止新增。主动清理成功后解除栈项引用，失败项保留到父级最终清理并传播原错误，不重复执行 cleanup。日志 sink 失败时立即停止分发，并通过微任务清理所属订阅 Effect，不改变日志调用和组件生命周期结果。

### Loader 生命周期重入

Loader 通过 Core 公开 Fiber 所有权链和生命周期状态识别自等待调用，不访问 Core 私有字段。外部服务失效也可能令 Entry 清理反向等待 Loader，不要求队列已有等待任务才识别该调用。只允许重入 `create()`：校验并登记后返回 `pending` 或适用的 `disabled`，延后解析和启动。其余等待型变更与 `awaitIdle()` 立即拒绝。普通 ACTIVE Root 调用仍进入串行队列。

### 删除与失败恢复

删除开始前标记目标子树，拒绝向其新增后代；无关分支和根的新条目仍可登记。删除尽可能完成所有清理和索引解除，等待后续协调后再报告清理错误，包括尚未显式恢复的历史清理失败。

清理失败独立阻断 Entry 自动重建，优先于 disabled、pending 和 active 的状态投影，启动回滚中的清理失败也遵守此规则。目标修改及 Registry 事件不解除阻断；只有 `resolve(id)` 显式恢复指定 Entry，后代自身的清理失败需分别恢复。禁用目标恢复为 disabled，启用目标复用有效 Fiber 或按最新安装目标重新安装。恢复不重跑已失败的旧 disposer，也不保证该失败不会在父级最终清理时再次报告。

### 解析定义缓存

Component 定义只在完整 Resolver 请求一致时复用，比较 id、name、parentId 与有效 baseUrl。异步结果只能提交给仍有效的原记录。Group 不走解析缓存。此协议处理解析输入变化，不提供同一模块的 HMR。

## 后果

- 生命周期中的创建成功仅表示 Entry 已登记；其他生命周期变更应从外层发起。
- 清理失败后的新目标保留，调用方可以检查错误并决定何时显式恢复。
- 删除 Promise 拒绝时条目也可能已经完全删除，应检查最终快照。
- 保持现有公共签名和错误对象，不增加强制 cleanup 超时。
- 测试需覆盖重入、失败与 Registry 通知交错，以及重复安装和删除后的资源基线。

## 考虑过的替代方案

允许所有 Loader 操作重入会引入第二套变更顺序和冲突处理。接受删除期间的新子条目再一起删除，会让成功创建结果立即失效，并允许清理不断扩展删除集合。清理失败后自动重建会掩盖未成功释放的资源。上述方案均不采用。
