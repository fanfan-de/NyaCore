# ADR-0005：运行时日志与 Effect 诊断不参与生命周期结果

> 状态：Accepted<br>
> 类型：ADR<br>
> 日期：2026-08-30

## 背景

Nya 已经使用 Fiber 和 Effect 统一管理组件启动、依赖变化、回滚和清理，但开发者只能从生命周期 Promise 的拒绝值判断失败。组件启动或卸载后，运行时缺少统一方式回答“哪个 Fiber 正在处理什么”“失败发生在哪个 Effect”以及“哪些资源仍处于清理中”。

诊断能力不能反过来改变被诊断对象。若日志 sink 的异常替换组件错误，或检查诊断树会取得可修改的内部对象，可观测性本身就会破坏生命周期语义。无限保留历史 Effect 和日志也会让诊断设施成为新的资源泄漏来源。

## 决策

### Logger 是每棵 Root 运行时内的旁路设施

- 每个 Root Context 拥有独立日志中心；派生 Context 的 `logger` 是绑定当前 Fiber 的轻量视图，自动附带组件、Fiber、run 和生命周期信息；
- 日志中心为当前 Root 保留最近 1000 条 `LogRecord`，容量超限时删除最旧记录；不同 Root 的日志和订阅互不相通；
- 记录先写入缓冲，再同步通知满足级别条件的 sink。sink 第一次抛错后立即移除，其错误只以 `logger/sink-failed` 写入缓冲，不再递归派发；
- 用户日志和自动生命周期日志都不得延迟状态转换、替换原错误或改变 Fiber 的成功、失败和清理结果；
- `logger.subscribe()` 返回由调用方 Fiber 拥有的 Disposer，因此订阅会随组件卸载或回滚自动取消。

### 诊断树旁路观察 Effect 所有权

- `fiber.inspect()` 返回新建且冻结的只读普通对象，不暴露可修改的运行时内部集合；
- 快照同时描述当前 run 以及最近一次失败 run。成功结束的更早历史不保留，避免诊断数据无限增长；
- Effect 节点记录稳定 ID、类型、标签、状态和父子关系；事件监听、服务注册、Logger 订阅和子组件安装使用结构化描述，不从展示标签反向解析身份；
- 嵌套错误以具体叶 Effect 路径优先，纯传播同一错误的祖先包装层不重复汇总；Service 失效与最终关闭分别记录为 `service-invalidate` 和 `service-finalize` 失败证据；
- 正在等待异步清理的 Effect 保持 `disposing` 并暴露状态更新时间。Core 不设置清理超时，也不把长时间 `disposing` 自动断言为资源泄漏；
- 启动、配置、Effect setup 或 cleanup 失败时，最近失败快照保留原始错误、阶段、停止原因和失败 Effect 路径，用于生命周期 Promise 拒绝后的事后检查。

### 明确观测边界与包边界

- Core 只能诊断通过 `context.effect()`、Event 监听、Service 注册、Logger 订阅和组件安装等公开协议登记的资源；绕过 Core 直接创建且未登记清理的定时器、文件句柄或网络连接无法被自动发现；
- Core 只提供结构化记录、内存缓冲和快照，不在导入时打印到控制台；
- 控制台格式化和输出属于独立的 `@nya/logger-console` Component。它只依赖 `@nya/core` 公开 API，显式安装后订阅日志，卸载后停止输出，导入包本身没有副作用。

## 后果

- 调用者仍以原生命周期 Promise 和原错误对象判断操作结果；日志只提供补充证据；
- `fiber.inspect()` 可以定位启动失败、清理失败和长期处于 `disposing` 的已登记 Effect，但不能证明任意宿主资源都已释放；
- 1000 条日志和一个最近失败 run 是固定的内存上界，代价是更早历史需要由外部 sink 持久化；
- Logger sink 必须被视为不可信观察者。其异常被隔离并自动取消，不会导致被观察组件进入 FAILED；
- 控制台输出策略可以独立演进，Core 继续不依赖宿主 console、文件系统或日志框架。

## 考虑过的替代方案

### Logger 失败时让生命周期失败

这样能让 sink 错误更显眼，但会使组件结果依赖可选观察设施，并可能覆盖真正的启动或清理错误，因此不采用。

### 保留全部历史日志和 Effect 运行

完整历史方便追溯，但长期进程中的内存占用没有上界。Core 采用固定缓冲与最近失败快照；长期存储交给外围 sink。

### Core 自动探测宿主资源或强制清理超时

JavaScript 运行时无法可靠枚举任意库创建的资源，统一超时也会把合法的长清理误判为泄漏。Core 只观察显式登记的所有权和状态，不自动中止清理。

### Core 导入后自动输出 console

自动输出会污染宿主进程并让格式策略进入最小核心。控制台行为由显式安装的外围 Component 提供。
